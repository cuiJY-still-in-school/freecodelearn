# PersonalAC 1.1 版本核心修改内容清单

本文档直接列出从 1.0 升级至 1.1 版本需要执行的核心修改内容，供开发实现直接参考。

---

## 1. UI 逻辑彻底重构 (UI Overhaul)

**目标：** 废除原有复杂的管理界面，回归“配置即用”的极简模式。

- [ ] **删除冗余界面**：移除教师管理、资源手动上传、复杂的仪表盘等所有非必要页面。
- [ ] **核心配置页**：仅保留一个核心配置入口，包含：
    - **Bot 设置**：输入 Token/凭证，安装通信 Bot。
    - **身份映射 (Mapping)**：建立“Bot 平台账号 ID <-> 系统角色 (学生/监护人)”的对应关系。
- [ ] **Email 插件开关**：增加一个可选的 Email API 配置入口，仅需输入邮箱账号和授权码。

---

## 2. 通信与角色逻辑调整 (Communication & Roles)

**目标：** 移除不切实际的社交关系，引入异步邮件接入。

- [ ] **彻底移除教师 IM 角色**：
    - 从数据库 `User` 表中删除 `teacher` 类型。
    - 移除 Bot 端所有关于教师好友验证、消息分发的逻辑。
- [ ] **新增 Email API 逻辑**：
    - **API 模式**：用户提供邮箱（主流邮箱如 Gmail, Outlook, QQ 等）。
    - **逻辑流**：Agent 轮询该邮箱 -> 解析新邮件 (正文+附件) -> 自动作为输入整合进 Workspace。
    - **外部贡献者身份**：不再定义为“教师”，统一通过发件人邮箱识别为“外部用户”。

---

## 3. 模型获取机制更新 (Model Discovery)

**目标：** 解决 API 商获取不稳定的问题，实现动态模型发现。

- [ ] **对接 models.dev**：
    - 废弃 1.0 中的静态模型列表或不稳定的获取方式。
    - 逻辑：`curl https://models.dev/api.json` -> 解码 JSON。
    - **动态加载**：每次配置或启动时自动拉取，让用户从返回的列表中选择模型。

---

## 4. Workspace 2.0 与存储策略 (Storage Strategy)

**目标：** 赋予 AI 极高的文件自主权，同时守住空间底线。

- [ ] **10GB 空间硬约束**：
    - 逻辑：`MAX_STORAGE = min(10GB, System_Available_Space)`。
    - 监控：实时计算 Workspace 文件夹大小，不足时禁止写入并触发清理。
- [ ] **AI 自主管理权**：
    - **“想放啥放啥”**：不再对 AI 读写文件做细粒度限制。
    - **自主清理**：在 10GB 空间告急时，允许 AI 根据策略（如删除旧的临时生成物）自主清理文件。
- [ ] **SQL 与 Workspace 联动**：
    - 确保 AI 能够通过 SQL 记录管理 Workspace 中的文件索引。

---

## 5. 数据库 (SQLite) 变更清单

- [ ] **表结构精简**：
    - `DROP TABLE` 相关的教师特定表（如有）。
    - `ALTER TABLE Resource`：增加 `source_email` 字段，删除 `teacher_id`。
- [ ] **新增配置项**：
    - `Settings` 表新增 `email_api_config` (JSON) 字段。
    - `Settings` 表新增 `last_model_json` 缓存字段。

---

**执行建议：** 优先完成 `models.dev` 的集成和 UI 的简化，再逐步接入 Email API 和 Workspace 空间管理逻辑。
