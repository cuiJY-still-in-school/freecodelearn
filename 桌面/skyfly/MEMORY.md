# 长期记忆

## 项目启动（2026-04-12）

**项目名称**：SkyFly（暂定）

**核心理念**：类似openclaw的AI工具，通过GUI或bot交互，帮助用户实现电脑上的一切操作。

**核心能力**：
- bash命令执行
- webfetch网络请求
- read/write/edit文件操作
- glob文件搜索

**核心技术**：AI自主探索的经验传递逻辑（混合方法架构）

**技术决策**：
- 选择混合方法（分层架构）作为1.0目标
- 推荐技术栈：Python + FastAPI + LangChain + React + ChromaDB
- 架构设计：向量检索层 + 案例推理层 + 学习优化层

**关键洞察**：
1. Python在AI生态中的优势不可替代
2. 经验传递需要分层处理：快速匹配 → 精确适配 → 长期优化
3. 安全性是首要考虑（AI执行bash命令的权限控制）

**项目状态**：需求和技术架构已定义，待确定最终技术栈并开始原型开发。

## 技术栈调整（2026-04-12 后续讨论）

### 新约束条件
1. **Python/Node.js担忧**：用户担心配置复杂、依赖冲突、"大佬"（大型库）多
2. **项目焦点**：复杂事务处理（如"在互联网上想尽一切办法赚钱"）
3. **部署模式**：双模式选择
   - 本地模式：仅限macOS/Linux
   - 沙箱模式：Ubuntu沙箱（虚拟机/容器）
4. **商业模式**：开源，主要供用户自己使用

### 重新设计的技术方案
**推荐架构**：Rust核心 + Python AI微服务

**理由**：
1. **Rust核心**：避免Python依赖冲突，高性能，内存安全，单二进制部署
2. **Python AI微服务**：隔离AI复杂依赖，利用Python生态优势
3. **微服务架构**：分离关注点，提高可维护性

**技术栈**：
- 核心引擎：Rust（Tokio, clap）
- AI服务：Python（FastAPI, LangChain）
- 前端：Tauri + React（轻量桌面应用）
- 数据库：SQLite + LanceDB/ChromaDB
- 沙箱：Docker/Firecracker

### 关键决策
1. 采用微服务架构解决Python依赖担忧
2. Rust负责工具执行和安全性
3. Python专注AI能力，容器化部署
4. 双部署模式（本地+沙箱）满足不同用户需求

**项目状态更新**：技术方案已重新设计，准备开始原型开发（Rust核心工具实现）。
