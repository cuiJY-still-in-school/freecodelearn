# AI时代产品项目

## 项目概述

**产品名称**：SkyFly（暂定）

**核心理念**：构建一个类似openclaw的AI工具，通过GUI或bot交互，帮助用户实现电脑上的一切操作。

**核心能力**：
- 通过自然语言指令控制计算机
- 执行bash命令
- 文件操作（read, write, edit, glob）
- 网络请求（webfetch）
- 自主探索和学习

**项目焦点**：
- 专注于**复杂事务处理**，如"在互联网上想尽一切办法赚钱"
- 目标导向的复杂任务自动化，而非单一领域工具
- 解决需要多步骤、跨工具、创造性解决方案的问题

**创新点**：
1. AI自主探索的经验传递逻辑
2. 类似opencode的工作方式但更通用
3. 经验积累和复用机制

**目标用户**：
1. **个人用户**：需要自动化复杂日常任务，如研究、数据收集、在线操作
2. **创业者/自由职业者**：需要自动化业务运营、市场研究、收入生成任务
3. **技术爱好者**：对AI自主探索感兴趣，希望扩展AI能力边界
4. **研究人员**：需要自动化实验、数据分析和文献调研

## 技术架构设计（经验传递混合方法）

### 分层架构设计

**1. 表层：快速检索层**
- **技术**：向量数据库（ChromaDB） + 语义嵌入
- **功能**：快速匹配用户自然语言需求与历史经验
- **输入**：用户自然语言指令
- **输出**：Top-K相似历史经验
- **算法**：
  - 使用语言模型（如text-embedding-ada-002）将任务编码为向量
  - 向量相似度搜索（余弦相似度）
  - 返回最相似的N个历史案例

**2. 中层：案例推理适配层**
- **技术**：结构化案例数据库 + 规则引擎
- **功能**：对检索到的案例进行适配和具体化
- **输入**：相似历史经验 + 当前任务上下文
- **输出**：适配后的具体行动计划
- **算法**：
  - 案例表示：`{问题描述，环境状态，执行步骤，结果反馈}`
  - 相似度计算：基于任务类型、环境、工具使用模式
  - 适配规则：变量替换（如`{filename}` → `当前文件`）、步骤调整

**3. 深层：学习优化层**
- **技术**：强化学习 + 元学习组件
- **功能**：长期策略优化和经验泛化
- **输入**：执行历史 + 反馈信号
- **输出**：优化后的策略参数
- **算法**：
  - 经验回放：存储成功/失败轨迹
  - 策略梯度：优化工具选择和参数设置
  - 元学习：快速适应新任务类型

### 数据流设计

```
用户请求 → 向量检索 → 案例匹配 → 案例适配 → 执行计划 → AI执行
     ↓          ↓          ↓          ↓          ↓          ↓
  自然语言  语义嵌入  相似度排序  规则适配  工具序列  环境交互
     ↓          ↓          ↓          ↓          ↓          ↓
  反馈收集 ← 结果评估 ← 执行监控 ← 计划执行 ← 计划生成 ← 计划优化
```

## 技术栈考虑

### 后端/核心引擎（主要选项）
**推荐方案**：
1. **Python（推荐）**：
   - ✅ AI/ML生态最丰富（TensorFlow、PyTorch、LangChain、HuggingFace）
   - ✅ 自主探索逻辑实现成本低
   - ✅ 快速原型开发
   - ⚠️ 性能相对一般，但对此类应用足够
   - 框架：FastAPI（API服务），LangChain（AI工作流）

2. **Node.js（备选）**：
   - ✅ 异步IO，适合CLI工具
   - ✅ JavaScript生态丰富（前端统一）
   - ⚠️ AI库相对Python较少，但可通过API调用
   - 框架：Express，Commander.js

**其他选项**：
3. **Go**：
   - ✅ 高性能，编译为单二进制文件
   - ✅ 并发处理优秀
   - ⚠️ AI生态较弱，需要自己实现或调用外部服务

4. **Rust**：
   - ✅ 内存安全，极致性能
   - ✅ 系统级编程能力
   - ⚠️ 学习曲线陡，AI生态有限

5. **Java/Kotlin**：
   - ✅ 企业级稳定性
   - ✅ JVM生态成熟
   - ⚠️ 相对笨重，启动慢

## 备注

### 关键挑战
1. **安全性**：AI执行bash命令需要严格权限控制
2. **可靠性**：自主探索可能导致不可预知的结果
3. **用户体验**：平衡自动化程度和用户控制

### 竞争分析
- **openclaw**：类似概念，参考对象
- **opencode**：类似工具集，但专注于代码开发
- **其他AI助手**：GitHub Copilot, Cursor等，但专注于特定领域

### 差异化优势
1. **经验传递逻辑**：AI可以从自己的探索中学习
2. **通用性**：不限于编程，涵盖计算机所有操作
3. **自主性**：AI可以主动探索解决方案

### 技术栈决策建议（基于新约束）

#### 约束条件分析
1. **Python/Node.js担忧**：用户担心配置复杂、依赖冲突、"大佬"多
2. **复杂任务需求**：需要强大的AI能力处理"在互联网上赚钱"等复杂目标
3. **部署模式**：本地（macOS/Linux） + 沙箱（Ubuntu）双模式
4. **开源个人使用**：简洁、可维护、避免过度工程

#### 重新设计的技术方案

**方案一：微服务架构（推荐）**
- **核心运行时**：Rust或Go
  - 优点：高性能、内存安全、单二进制部署、无复杂依赖
  - 负责：工具执行（bash、文件操作）、沙箱管理、任务调度
- **AI服务**：Python微服务
  - 优点：利用Python AI生态，但隔离复杂依赖
  - 负责：自然语言理解、经验检索、规划决策
- **通信**：gRPC或REST API
- **部署**：Docker容器，核心运行时 + AI服务分离

**方案二：精简Python方案**
- **核心**：Python + 严格依赖管理
- **工具**：使用conda/pipenv/poetry管理虚拟环境
- **打包**：PyInstaller/Nuitka打包为单文件
- **优点**：保持Python生态优势，但通过打包简化部署

**方案三：WebAssembly隔离**
- **核心**：Rust/Go运行时
- **AI组件**：Python编译为WebAssembly，在沙箱中运行
- **优点**：完全隔离，安全，但性能开销大

#### 具体技术选择建议

**推荐方案：Rust核心 + Python AI微服务**

**后端架构**：
1. **核心引擎（Rust）**：
   - 框架：Tokio（异步运行时），clap（命令行解析）
   - 功能：工具执行管理、沙箱控制、任务流水线
   - 优点：性能好、内存安全、部署简单

2. **AI服务（Python）**：
   - 框架：FastAPI（API服务），LangChain（AI工作流）
   - 功能：自然语言处理、经验检索、规划生成
   - 部署：Docker容器，依赖隔离

3. **前端界面**：
   - **桌面应用**：Tauri + React（Rust后端，轻量）
   - **Web界面**：React + 后端API
   - 优点：Tauri比Electron更轻量，与Rust核心集成好

4. **数据库**：
   - **本地存储**：SQLite（嵌入式，简单）
   - **向量检索**：LanceDB（Rust原生）或 ChromaDB（Python服务内）
   - **缓存**：SQLite内存表 或 Redis（可选）

5. **沙箱技术**：
   - **容器**：Docker/Podman
   - **虚拟机**：Firecracker（轻量VM）
   - **权限控制**：Linux namespaces/cgroups

#### 实施路径
1. **第一阶段**：Rust核心实现基础工具（bash, read, write, edit, glob）
2. **第二阶段**：Python AI服务实现自然语言理解和简单规划
3. **第三阶段**：集成前端界面和沙箱管理
4. **第四阶段**：实现经验传递系统

### 风险与缓解
1. **Rust学习曲线**：团队成员需要学习Rust → 从简单工具开始，逐步深入
2. **Python依赖管理**：AI服务依赖复杂 → 使用Docker容器隔离
3. **跨语言通信**：Rust-Python接口性能 → 使用protobuf/gRPC优化
4. **沙箱安全性**：AI执行命令的安全风险 → 严格的权限控制和操作确认
